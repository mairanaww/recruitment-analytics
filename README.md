# Recruitment Analytics Pipeline

This project is a robust, end-to-end data pipeline built for recruitment analytics and headcount planning. It demonstrates the ability to ingest raw data, enforce database constraints, perform idempotent ETL loads, and expose analytics-ready dimensional and metric views.

> **Note:** The data generated by this project is entirely synthetic. It is designed to mimic realistic recruitment funnel volumes, seasonal hiring patterns, and plausible drop-off rates by stage. The primary deliverable of this project is the **reporting infrastructure and ETL pipeline**, not the findings about the fictional candidates.

## Architecture

1. **Synthetic Data Generator:** A Python script utilizing `Faker` to generate normalized CSVs representing a source system.
2. **PostgreSQL Database:** A local relational database spun up via Docker, featuring a normalized schema with constraints.
3. **Python ETL:** A Command Line Interface (CLI) tool using `pandas` and `SQLAlchemy` that performs idempotent upserts (handling duplicates and changes safely) and logs runs.
4. **SQL Analytics Layer:** Two sets of views:
   - **Metric Views:** Used for flat reporting (time-to-fill, offer acceptance rates).
   - **BI Star Schema:** Dimensional and fact tables tailored for Power BI slicing, dicing, and drill-through.
5. **Excel Exporter:** A Python script using `openpyxl` to automate a formatted weekly report.

## Setup Instructions

### Prerequisites
- Python 3.9+
- Docker Desktop
- A `.env` file based on `.env.example`

### 1. Initialize the Environment
```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Generate Synthetic Data
```bash
python src/generate_data.py
```
This will populate `data/raw/` with several CSV files.

### 3. Spin Up PostgreSQL & Setup Schema
```bash
# Start the database
docker-compose up -d

# Wait a few seconds for postgres to be ready, then run:
export PGPASSWORD=secret
psql -h localhost -U postgres -d recruitment -f sql/schema.sql
psql -h localhost -U postgres -d recruitment -f sql/analytics_views.sql
psql -h localhost -U postgres -d recruitment -f sql/bi_views.sql
```

### 4. Run the ETL Pipeline
```bash
# Run the pipeline (loads CSVs into Postgres)
python src/etl.py

# You can test idempotency by running it again; it will safely update/skip without duplicating records.
python src/etl.py
```

### 5. Generate Weekly Excel Report
```bash
python src/export_excel.py
```
Check the `reports/` folder for the formatted output.

### 6. Run Tests
```bash
pytest tests/
```
The test suite explicitly verifies the idempotent upsert logic (e.g. COUNT(*) does not change on rerun, but modified fields do update).

## Power BI & Mac Environment Considerations

Power BI Desktop is a Windows-only application. If you are on a Mac, you have a few options to build the `.pbix` dashboard:

1. **Parallels Desktop (Recommended):** Use the 14-day free trial with Windows 11. This is the smoothest experience.
2. **UTM:** A free, open-source alternative. It can run Windows 11 ARM on Apple Silicon, though it requires slightly more setup.
3. **Campus Lab Machine:** Many universities provide Windows lab machines. You can build the dashboard there and carry the `.pbix` file on a USB drive.

**Crucial Networking Caveat:**
If you run Power BI inside a VM (like Parallels) on your Mac, it needs to connect to the PostgreSQL database running on your Mac host. 
- **Do NOT** use `localhost` in Power BI, as that will point to the VM itself.
- **DO** use the IP address of your host machine. For Parallels, this is usually `10.211.55.2`. Point Power BI to `10.211.55.2:5432`.

Connect Power BI to the `bi_fact_*` and `bi_dim_*` views to leverage the star schema for optimal cross-filtering and DAX measures.
